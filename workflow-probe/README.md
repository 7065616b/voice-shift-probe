# Workflow Probe

**평소 동작은 통과하는 앱의 숨은 오류를, 조건을 바꾸어 찾아내는 브라우저 검증 도구.**

게임에서 상대에게 평소와 다른 행동을 해보면 반응 차이가 드러난다는 관찰에서 출발했습니다. 음성 연구에서 사용한 ‘원본과 변형 조건의 비교’를 웹 앱의 업무 규칙 검증으로 옮겼습니다. 이 첫 버전은 학습된 AI 모델이 아니라, 명시한 규칙과 실제 브라우저 관찰을 연결하는 실행 가능한 프로토타입입니다.

## 검사하는 약속

| 조건 변화 | 유지되어야 하는 결과 | 발견하는 오류 |
|---|---|---|
| 상품 순서를 바꾸기 | 같은 상품의 합계 금액 | 잘못된 합계 재계산 |
| 같은 저장 의도로 두 번 누르기 | 저장은 한 건 | 중복 주문 생성 |
| 저장 후 새로고침 | 저장 내역이 화면에 계속 표시 | 재조회 후 저장 내역 표시 누락 |

중복 저장 방지는 **이 예제 앱의 요구사항**입니다. 모든 버튼을 두 번 누르면 한 번만 처리되어야 한다는 일반 규칙은 아닙니다. 새로고침 오류는 표시 누락이며, 저장소의 데이터 삭제를 뜻하지 않습니다.

## 실행

Node.js 22 이상, Chromium이 필요합니다. 저장소 루트에서:

```sh
cd workflow-probe
npm ci
npx playwright install chromium
npm test
npm run probe
npm run verify
npm run report
npm run demo
```

`http://127.0.0.1:8787/report/`에서 결과를 보고, `http://127.0.0.1:8787/`에서 정상 예제 앱을 사용합니다. 무료 로컬 실행이며 GPU가 필요 없습니다. `PLAYWRIGHT_PACKAGE`는 이미 설치한 Playwright 모듈의 경로를 선택하는 선택적 환경 변수입니다.

## 실제 기록과 검증 범위

앱 5개 버전(오류 3종, 정상 1종, 외관만 바꾼 정상 1종) × 조건 3종 × 반복 3회 = **45회 검사**입니다. 정상 사용 경로를 별도의 세션에서 먼저 확인합니다. 각 조건 검사도 독립 세션으로 실행합니다.

Windows 로컬과 [별도 Linux 자동 실행](https://github.com/7065616b/voice-shift-probe/actions/runs/36955561736)에서 같은 결과를 확인했습니다. 심어 둔 오류 3종을 각각 3/3회 재현했고, 정상 대조군 18회에서 오신고 0건, 실행 실패 0건입니다. 평소 경로 45/45가 통과한 상태에서 조건 변화로만 오류를 발견했습니다. 코드 테스트 10개와 보고서 검사 6개도 통과했습니다.

결과는 [원본 관찰](report/results.json), [독립 평가](report/evaluation.json), [코드·증거 지문](report/provenance.json)에서 확인할 수 있습니다. 공개 자료에는 코드와 수치·행동 기록을 보존합니다. 90개 변경 전후 화면과 9개 Playwright 추적 ZIP은 로컬 재실행 시 생성하며 공개 업로드에서 제외했습니다. 원본 관찰 JSON의 artifact 경로는 로컬 재실행 결과를 가리킵니다. GitHub Actions의 보고서 아티팩트에도 HTML·JSON만 포함합니다.

검사기는 오류 이름으로 결과를 정하지 않습니다. 실제 금액·주문 수·항목 순서와 요청 완료를 관찰해 판단하고, 별도의 평가기가 심어 둔 오류 목록과 비교합니다. 검사 실행 실패는 제품 오류 발견과 따로 집계합니다. 정상 앱의 외관 변화는 업무 값이 유지되면 신고하지 않습니다.

**직접 심은 오류를 찾은 결과는 실제 서비스의 탐지 정확도가 아닙니다.** 아직 다른 사람이 만든 앱, 실제 고객 환경, 새로운 오류 유형을 검증하지 않았습니다. 이 방식은 메타모픽 테스팅이라는 기존 연구 원리이며, 사용자 경험에서 구체적인 조건과 업무 규칙을 도출한 과정이 이 프로젝트의 기여입니다.

## 다음 확장

실제 앱 하나의 요구사항에서 ‘바뀌어도 유지될 값’을 먼저 정하고, 버튼·페이지·완료 신호를 연결하는 앱별 어댑터를 만듭니다. 알려진 오류를 보지 않은 상태에서 검사한 뒤 기존 테스트와 비교하면 실용적인 효과를 평가할 수 있습니다. 현재 검사기는 임의의 웹사이트를 범용으로 검사하지 않습니다.

## 근거와 개발 기록

- [메타모픽 테스팅 원 논문](https://www.cse.ust.hk/faculty/scc/publ/CS98-01-metamorphictesting.pdf): 입력 변화와 결과 사이의 관계를 검증하는 방법.
- [Playwright Trace Viewer](https://playwright.dev/docs/trace-viewer): 브라우저 동작과 화면 기록 재현.
- [설계와 완료 기준](workflow/plan.md), [검증 계획](docs/validation-plan.md), [QA 결과](workflow/qa.md).

개발은 사용자와 Codex가 함께 진행했습니다. 예제 앱, 브라우저 검사기, 독립 검증 검토를 각각 보조 에이전트에 맡기고 루트 에이전트가 보고서·통합·실행 검증을 담당했습니다. 자동 생성 코드의 실행 결과와 한계를 함께 공개합니다.
